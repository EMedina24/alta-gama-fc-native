What the code already decides
KICKOFF REMINDER
Local, not push — scheduled on device 30 minutes ahead, 60-slot budget, 21-day horizon. A TBD kickoff is never scheduled. Copy is fixed in copy.reminders.
MOVED & POSTPONED
Server push, gated on alertMoved / alertPostponed. Both carry thread-id: fixture-{uuid} so repeats collapse. Copy is server-owned — these two strings need your sign-off.
EVERY TAP
One destination: altagamafc://club/{slug}. Local and server payloads share a shape so one handler routes both, and an unknown type opens the app rather than crashing.
TWO THINGS TO DECIDE BEFORE BUILD
Crests need a Notification Service Extension. iOS allows one attachment per notification, so the two-crest thumbnail has to be composed — server-side into a single PNG, or in an NSE that downloads both and draws them. The local kickoff reminder cannot run an NSE at all: it must attach a crest already cached on disk, or ship without one. Worth confirming we want to carry that extension.
Crests are LaLiga-only today. Premier League, Bundesliga and Serie A clubs have no published crest, so their notifications fall back to the abbreviation tile — the same treatment the club list uses. Both directions above need that variant drawn before handoff.
My read: ship 1a as the short look and add 1b as the long-press expansion for moved and postponed only — the kickoff reminder does not earn a custom view. Tell me which way and I will draw the no-crest fallback, the grouped stack, and the Spanish strings.
